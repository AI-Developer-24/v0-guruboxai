# SEO Round 2 Public-Example Page Definitions

Last updated: 2026-05-06
Status: Drafted for implementation planning
Related framework: [seo_round2_page_definition_framework.md](./seo_round2_page_definition_framework.md)
Related plan: [seo_round2_execution_plan.md](./seo_round2_execution_plan.md)

## Purpose

This document defines the first expansion batch for public example pages before implementation.

These pages extend the existing sample-report strategy beyond:
- freelancers
- small business

All routes in this set should launch in:
- `en`
- `zh`

All routes should keep English slugs for locale consistency:
- `/en/examples/...`
- `/zh/examples/...`

## Shared Rules

### Shared CTA pattern

- Primary CTA: `Start analysis`
- Secondary CTA: `View another sample`

### Shared page purpose

Every page in this cluster should:
- prove output quality before login
- focus on one concrete market slice
- show ranked wedges instead of generic AI-tool lists
- explain why the top wedge scored higher than the alternatives
- leave the visitor with a clear next move into the product

### Shared content expectations

Every page in this cluster should include:
- scenario brief
- audience definition
- repeated workflow pain
- top ranked opportunities
- why-now or score logic
- practical next move
- FAQ
- related workflows and related samples

### Shared visual direction

- report-like and concrete
- slightly denser than homepage and core pages
- strong scenario framing
- more “public research memo” than “marketing showcase”

- `public-example-recruiters`

### Route slug

- `/[locale]/examples/ai-tools-for-recruiters`

### Launch locales

- `en`
- `zh`

### Page type

- `Type D: Public Example`

### Primary intent

- Capture search intent around `ai tools for recruiters`

### Supporting intents

- `recruiting workflow ai examples`
- `ai tools for interview summaries`
- `public sample report for recruiting ai workflows`

### Primary CTA

- Start an analysis for a recruiting workflow

### Secondary CTA

- View another public sample report

### Required content blocks

1. Hero with scenario promise:
   - recruiting workflows with repeated note-to-summary friction
2. Scenario brief:
   - boutique recruiters and in-house screening teams
3. Ranked opportunities:
   - interview notes to candidate summary
   - recruiter call recap to follow-up workflow
   - role brief to candidate-fit comparison
4. Why the top wedge wins:
   - repetition
   - time-to-response pressure
   - monetizable operational pain
5. Next move guidance:
   - when to run your own analysis
6. FAQ
7. Related workflows and related samples
8. CTA

### Preferred visual direction

- recruiting-ops memo
- concrete and speed-sensitive
- should feel operational, not HR-generic

### Mandatory internal links

- homepage: `/[locale]`
- core workflow: `/[locale]/saas-idea-validation`
- use-case page: `/[locale]/use-cases/ai-tools-for-recruiters`
- related sample: `/[locale]/examples/ai-tools-for-freelancers`

### Success metric

- impressions for recruiter-intent queries
- click-through from sample readers into analysis

### Differentiation note

This page should not drift into general AI-for-HR content.
It needs to stay anchored in recruiter workflow friction that can justify paid software wedges.
