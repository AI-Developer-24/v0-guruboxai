## Purpose

This document defines the first how-to cluster before implementation.

All routes in this set should launch in:
- `en`
- `zh`

All routes should keep English slugs for locale consistency:
- `/en/guides/...`
- `/zh/guides/...`

## Shared Rules

### Shared CTA pattern

- Primary CTA: `Start analysis`
- Secondary CTA: `View sample report`

### Shared content expectations

Every page in this cluster should:
- solve one instructional query
- provide a repeatable step sequence
- include at least one worked example
- explain one or two common mistakes
- end by pointing into a concrete product workflow

### Shared visual direction

- editorial process page
- quieter and more structured than the homepage
- section rhythm should emphasize ordered steps
- minimal decorative chrome, stronger information hierarchy

## Page 1

### Page ID

- `how-to-validate-an-ai-startup-idea`

### Route slug

- `/[locale]/guides/how-to-validate-an-ai-startup-idea`

### Launch locales

- `en`
- `zh`

### Page type

- `Type B: How-To`

### Primary intent

- Capture search intent around `how to validate an ai startup idea`

### Supporting intents

- `validate ai startup idea`
- `how to test an ai saas idea`
- `is this ai startup worth building`

### Primary CTA

- Start an idea-validation workflow

### Secondary CTA

- Review a public sample report first

### Required content blocks

1. Hero with promise:
   - validate before building
2. Problem statement:
   - most founders confuse idea generation with idea validation
3. Step-by-step process:
   - narrow the market
   - identify repeated pain
   - compare candidate wedges
   - inspect willingness-to-pay signals
   - decide what to test first
4. Worked example:
   - one input direction
   - one ranked output set
5. Mistakes to avoid:
   - choosing a market that is too broad
   - relying on generic brainstorming alone
   - skipping operational pain
6. FAQ
7. CTA

### Preferred visual direction

- process-led
- slightly more editorial than product-led
- should read like a practical operating guide, not a motivational article

### Mandatory internal links

- homepage: `/[locale]`
- core workflow: `/[locale]/saas-idea-validation`
- core workflow: `/[locale]/ai-startup-idea-generator`
- public example: `/[locale]/examples/ai-tools-for-freelancers`

### Success metric

- impressions and CTR for validation-intent keywords
- click-through into a validation workflow

### Differentiation note

This page should teach a method, not just pitch the product.
Its job is to capture instructional intent and then bridge into the validation workflow naturally.

- `how-to-prioritize-ai-business-opportunities`

### Route slug

- `/[locale]/guides/how-to-prioritize-ai-business-opportunities`

### Launch locales

- `en`
- `zh`

### Page type

- `Type B: How-To`

### Primary intent

- Capture search intent around `how to prioritize ai business opportunities`

### Supporting intents

- `prioritize ai opportunities`
- `how to rank ai startup ideas`
- `which ai workflow should i build first`

### Primary CTA

- Start an opportunity-analysis workflow

### Secondary CTA

- View a public sample report first

### Required content blocks

1. Hero with promise:
   - choose what deserves the next move
2. Problem statement:
   - founders and operators see too many possible wedges at once
3. Step-by-step process:
   - define one market slice
   - map repeated workflow pain
   - compare urgency and willingness to pay
   - inspect implementation complexity
   - rank the short list
4. Worked example:
   - show why one wedge outranks another
5. Mistakes to avoid:
   - overvaluing novelty
   - ignoring repeated operational pain
   - ranking without visible criteria
6. FAQ
7. CTA

### Preferred visual direction

- analytical tutorial
- stronger comparison rhythm between steps
- should feel closer to a prioritization memo than a marketing page

### Mandatory internal links

- homepage: `/[locale]`
- core workflow: `/[locale]/ai-business-opportunity-analysis`
- public example: `/[locale]/examples/ai-tools-for-small-business`
- future reserved link: comparison page between idea generation and opportunity analysis

### Success metric

- impressions for prioritization-intent queries
- clicks into the opportunity-analysis flow

### Differentiation note

This page should answer “how do I rank competing AI opportunities?” instead of broadly explaining AI startup strategy.

## Page 3

### Page ID

- `how-to-find-an-ai-saas-wedge`

### Route slug

- `/[locale]/guides/how-to-find-an-ai-saas-wedge`

### Launch locales

- `en`
- `zh`

### Page type

- `Type B: How-To`

### Primary intent

- Capture search intent around `how to find an ai saas wedge`

### Supporting intents

- `find ai saas wedge`
- `ai saas niche selection`
- `how to narrow an ai startup idea`

### Primary CTA

- Start an idea-generation workflow

### Secondary CTA

- Compare with a public sample first

### Required content blocks

1. Hero with promise:
   - narrow a broad AI idea into a wedge worth testing
2. Problem statement:
   - broad AI markets rarely produce focused products by themselves
3. Step-by-step process:
   - start from a market, not a model capability
   - identify a repeated operator workflow
   - narrow by urgency and context
   - compare several wedge candidates
   - keep only the strongest next test
4. Worked example:
   - broad market to wedge shortlist
5. Mistakes to avoid:
   - building for “everyone”
   - picking a wedge without workflow repetition
   - confusing general AI features with software value
6. FAQ
7. CTA

### Preferred visual direction

- narrow and strategic
- should feel like a practical founder note
- more focused than the homepage, less dense than comparison pages

### Mandatory internal links

- homepage: `/[locale]`
- core workflow: `/[locale]/ai-startup-idea-generator`
- public example: `/[locale]/examples/ai-tools-for-freelancers`
- future reserved link: comparison page versus manual market research

### Success metric

- impressions and CTR for wedge-selection queries
- click-through into the idea-generation workflow

### Differentiation note

This page should help visitors move from vague market interest to a narrower software wedge.
It should not drift into generic “how to start a SaaS” advice.
