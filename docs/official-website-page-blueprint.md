# Official Website Page Blueprint

## Purpose

This document defines the canonical page blueprint for the public website. It is not a code-level spec. It is the content, structure, and responsibility blueprint that should guide future implementation.

The key principle is:

**Homepage = trust + routing. Child pages = intent fulfillment + conversion.**

## Public Site Map

### Marketing Page Families

1. Homepage
2. Core workflow pages
3. Guide pages
4. Comparison pages
5. Use-case pages
6. Public example pages
7. Legal pages

### Product/App Pages

1. Product tool entry
2. Private analysis pages
3. Private report pages
4. Account pages

These app pages are product surfaces, not public SEO targets.

## Navigation Blueprint

### Recommended Primary Navigation

- `Home`
- `Workflows`
- `Use Cases`
- `Examples`
- `Learn`
- `Start Analysis`

### Why

- `Workflows` groups the 3 highest-intent product-entry pages.
- `Use Cases` groups audience and role pages.
- `Examples` groups public proof pages.
- `Learn` groups guides and comparisons.
- This separates user intent layers instead of mixing everything into homepage content.

## Homepage Blueprint

### Homepage Role

The homepage should not be a complete content directory. It should:

- explain what BadgerSignal is
- establish trust
- route visitors to the right next page
- provide a small amount of public proof

### Homepage Module Order

#### 1. Hero

Purpose:

- state product value clearly
- set the primary action
- introduce the public proof path

Must contain:

- eyebrow or category label
- H1 with the broad product promise
- one concise description paragraph
- primary CTA: `Start Analysis`
- secondary CTA: `View Sample Report`
- concise hero visual showing the product motion

Must not contain:

- long process explanation
- many alternate entry links

#### 2. Pick Your Workflow

Purpose:

- route the visitor into the correct core product decision path

Must contain:

- 3 core workflow cards only
- each card answers:
  - what question this workflow solves
  - when to use it
  - what kind of output to expect

Cards:

- AI startup idea generator
- SaaS idea validation
- AI business opportunity analysis

Must not contain:

- guides
- comparisons
- public examples

#### 3. See Sample Output

Purpose:

- prove output quality before login

Must contain:

- 2 to 3 strongest public sample pages
- a section intro that explains why sample pages exist
- cards that show:
  - scenario
  - what is being ranked
  - why the sample is useful

Recommended sample pages to feature:

- recruiters
- agencies
- freelancers or ecommerce operations

#### 4. Learn Before You Try

Purpose:

- serve visitors who are still educating themselves and are not ready to choose a workflow yet

Must contain:

- 2 guides
- 1 or 2 comparisons
- lightweight cards, not dominant cards

Recommended items:

- how to validate an AI startup idea
- how to prioritize AI business opportunities
- BadgerSignal vs ChatGPT

Must not contain:

- another “how to choose the homepage” explanation

#### 5. Final CTA

Purpose:

- close the page with one clear next move

Must contain:

- one strong CTA
- optional one secondary CTA
- no repeated explanation of the full product motion

### Homepage Content Rules

- Each section must answer one distinct question only.
- No section should restate the previous section’s explanation.
- The homepage should not repeat the same “choose the right page” message multiple times.
- The homepage should not retell the same workflow story in hero, middle, and lower sections.

## Core Workflow Page Blueprint

### Role

Fulfill high-intent search demand and convert visitors who already know the kind of product decision they need to make.

### Core Workflow Module Order

#### 1. Hero

- keyword-focused H1
- concise description
- primary CTA
- one compact workflow visual

#### 2. Best For / Not For / Use It When

- who this page is for
- who should choose another page
- what decision stage this workflow fits

#### 3. What You Get

- 3 outcome cards
- concrete outputs, not abstract benefits

#### 4. Input / Output Example

- what the user brings in
- what the workflow returns

#### 5. Why This Workflow Instead of ChatGPT

- one comparison block
- explain where structured scoring and prioritization matter

#### 6. Public Proof

- link to one or two example pages

#### 7. FAQ

- real search questions

#### 8. CTA

- one conversion CTA

## Guide Page Blueprint

### Role

Answer instructional search intent and educate visitors into the right workflow.

### Guide Module Order

#### 1. Hero

- direct how-to title
- who this guide is for

#### 2. Why This Guide Exists

- the common mistake this guide prevents

#### 3. Step-by-Step Framework

- clear ordered steps

#### 4. Signals to Look For

- what makes a wedge promising

#### 5. Mistakes to Avoid

- anti-patterns

#### 6. Where BadgerSignal Helps

- connect the guide back to product value

#### 7. Related Workflow and Sample

- route visitors deeper

#### 8. FAQ

#### 9. CTA

## Comparison Page Blueprint

### Role

Serve evaluation intent and help visitors choose between two methods or tools.

### Comparison Module Order

#### 1. Hero

- a direct verdict angle

#### 2. Quick Comparison Frame

- concise comparison table or criteria block

#### 3. When to Use A

#### 4. When to Use B

#### 5. Limits and Tradeoffs

- balanced, not shallow “winner” copy

#### 6. Related Workflow

- route to the best next product page

#### 7. FAQ

#### 8. CTA

## Use-Case Page Blueprint

### Role

Translate product value into role-specific or industry-specific workflow pain.

### Use-Case Module Order

#### 1. Hero

- role/industry-specific H1
- one tight summary of repeated workflow pain

#### 2. Why This Audience Matters

- explain the market slice

#### 3. Repeated Workflow Pain

- 3 specific pains

#### 4. Best Product Wedges

- ranked or grouped opportunity lanes

#### 5. Which Workflow to Use Next

- generator vs validation vs opportunity analysis

#### 6. Public Example Link

- bridge to proof

#### 7. FAQ

#### 8. CTA

## Public Example Page Blueprint

#### 7. CTA

## Blueprint Summary

### Core Principle

- Homepage routes
- Child pages satisfy
- Example pages prove
- Guides teach
- Comparisons evaluate
- Product entry converts

### Anti-Patterns to Avoid

- Homepage as complete content directory
- repeated “how to choose” sections
- repeating hero logic in lower sections
- mixing workflow, guide, sample, and comparison cards at the same visual weight
- using homepage to explain everything the site already has dedicated pages for
